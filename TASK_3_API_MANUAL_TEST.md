# Task 3 - Manual API Testing Guide

## Prerequisites

- Backend is running at `http://localhost:3000` with global prefix `/api`.
- `DATABASE_URL` points to a working Postgres instance.
- Seed is executed at least once:

```bash
npx prisma db seed
```

This creates:
- Default roles/permissions
- Default admin user:
  - email: `admin@vhandelivery.com`
  - password: `admin123`

## Import Postman Collection

- Import file: `TASK_3_API_COLLECTION.postman_collection.json`
- Set collection variables as needed.

Default `baseUrl` in collection:

- `http://localhost:3000/api`

## Notes about OTP

OTP is generated by `POST /merchants/otp/request` and printed to server logs:

- Look for log like:

```
[OTP-DEBUG] OTP for 098xxxxxxx: 123456
```

Copy that `123456` into Postman variable `otpCode` before calling `POST /merchants/otp/verify`.

## Suggested Execution Order (Happy Path)

### 1) Admin login

- Run: `Auth/POST /auth/login (admin)`
- This sets `adminAccessToken`.

### 2) Register users (merchant owner + customer)

- Run:
  - `Auth/POST /auth/register (merchant owner)`
  - `Auth/POST /auth/register (customer)`

This sets:
- `merchantOwnerAccessToken`
- `customerAccessToken`

### 3) Merchant registration (OTP)

- Run: `Merchant/POST /merchants/otp/request`
- Read OTP from server log, set Postman variable `otpCode`
- Run: `Merchant/POST /merchants/otp/verify`
  - sets `verificationToken`
- Run: `Merchant/POST /merchants/register (self-register)`
  - sets `merchantExternalId`

### 4) Admin approves merchant

- Run: `Merchant/PATCH /merchants/:externalId/status (admin approve)`

This step should:
- set merchant approval to APPROVED
- auto-assign `MERCHANT_OWNER` role to merchant owner and link `merchantId` (internal numeric)

### 5) Get numeric `merchantId`

- Run: `Merchant/GET /merchants/:externalId (get numeric merchantId)`
  - sets `merchantId`

### 6) Merchant creates product (DRAFT) then publishes

- Run:
  - `Product/POST /products (create DRAFT)`
    - sets `productExternalId`
  - `Product/PATCH /products/:externalId (publish)`

### 7) Customer storefront + cart + order

- Run:
  - `Storefront (B2C)/GET /storefront/products`
  - `Cart/POST /carts/merchant/:merchantId/items`
  - `Order/POST /orders/merchant/:merchantId (create from cart)`
    - sets `orderId`

## Courier flow (optional / advanced)

Current codebase does not expose an endpoint to create a courier record for a user.
To fully test courier assignment logic, you may:

- Create courier user (`Auth/POST /auth/register (courier)`)
- Then create courier record directly in DB (Prisma Studio / SQL) and set:
  - `couriers.user_id` = created user id
  - `couriers.approval_status` = `APPROVED`
  - `couriers.online_status` = `ONLINE`
  - set `user_roles.role` = `COURIER`

Once courier exists, you can use:
- `Courier/PATCH /couriers/:id/approve (admin)`
- `Courier/PATCH /couriers/me/status`
- `Courier/PATCH /couriers/me/location`

## Troubleshooting

### 401 Unauthorized

- Ensure you have a valid `Authorization: Bearer <token>` header.
- Re-run login/register requests to refresh the access token.

### 403 Forbidden

- Check permissions:
  - Merchant endpoints require admin permissions or correct ownership.
  - Product create requires merchant to be APPROVED and user to have MERCHANT_OWNER scope.

### 400 Bad Request

- OTP verify requires correct `otpCode` and unexpired record.
- Product create requires `merchantId`, `name`, `sku`, `price`, `stock`.
